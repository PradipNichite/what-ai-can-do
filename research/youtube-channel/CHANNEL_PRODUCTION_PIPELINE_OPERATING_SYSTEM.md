# Channel Production Pipeline Operating System

This document defines how the channel should produce videos consistently without depending on daily motivation, last-minute decisions, or expensive rework.

## Core Operating Philosophy

Do not launch the channel with only one or two videos.

Launch when there is enough finished and near-finished inventory to survive low-motivation weeks.

Recommended launch condition:

```text
10 finished Shorts in one flagship playlist
10-20 additional scripts/storyboards ready
at least 3 future playlist/topic clusters planned
```

The channel should operate like a pipeline, not like isolated creative bursts.

## Why A Pipeline Matters

The biggest risks are:

- publishing a few videos and then stopping
- spending money on images or video generation before the idea is clear
- creating visuals that look good but do not teach the concept
- losing prompts, decisions, and useful production knowledge
- delaying publishing because voiceover is not ready
- rebuilding the same structure every time
- making each video feel like a fresh blank page

The pipeline should protect against all of these.

## Pipeline Principle

Each video must pass through stage gates.

Do not move to the next expensive stage until the current stage is good enough.

```text
Topic -> Learning Core -> Scene Plan -> Image Prompts -> Image QA -> Image-to-Video Prompts -> Motion QA -> Voiceover -> Assembly -> Final QA -> Scheduled
```

The important rule:

```text
Money is spent only after clarity is achieved.
```

## Work-In-Progress Model

The channel should always have work at multiple stages.

Example:

```text
Playlist 1: image generation / motion generation
Playlist 2: scene plans complete
Playlist 3: topic and learning cores complete
Playlist 4: rough topic research
```

This creates a buffer. If voiceover is blocked, script work continues. If image generation is blocked, future playlists can still be planned. If motivation is low, the next task is already known.

## Production Stages

### Stage 1: Channel Direction

Status:

```text
Done for the current phase.
```

Current direction:

```text
Class 9-12 math concepts explained through real AI mechanisms.
```

Current flagship series:

```text
Class 9-12 Math Inside AI
```

Current format emphasis:

```text
Shorts-first, not Shorts-only.
```

### Stage 2: Three-Month Content Map

Before launch, define the next three months of content.

Minimum:

- 3 playlists or topic clusters
- 30 Shorts topics
- 3-6 long-form candidates
- clear order of publishing

Recommended structure:

| Month | Primary output | Purpose |
|---|---|---|
| Month 1 | 10 Shorts in one playlist | prove the core promise |
| Month 2 | 10 Shorts + 1-2 long videos | test expansion and trust |
| Month 3 | 10 Shorts + 1-2 long videos | build session depth |

### Stage 3: Playlist Definition

Each playlist needs a one-line promise before any scripts are written.

Template:

```text
Playlist name:
Audience:
Promise:
What it includes:
What it excludes:
Recommended video count:
```

Example:

```text
Playlist name: Why Am I Learning This?
Audience: Class 9-12 students curious about AI
Promise: Each video shows where one Class 9-12 math concept appears inside AI.
Includes: matrices, vectors, probability, statistics, functions, derivatives
Excludes: exam solving, proofs, coding tutorials
Video count: 10-15
```

### Stage 4: Video Learning Core

Every video needs a learning core before scene writing.

Template:

```text
Video title:
School concept:
AI mechanism:
Learner question:
Misconception:
Core explanation:
Visual transformation:
Memory sentence:
Next linked video:
```

Gate to continue:

- The school concept is clear.
- The AI mechanism is real.
- The memory sentence is simple.
- The video teaches one idea only.

If this stage is weak, do not write scenes yet.

### Stage 5: Scene Plan

Only after the learning core is approved, create the scene plan.

For Shorts, use 5-7 scenes.

Template:

```text
Scene number:
Duration:
Visual:
On-screen text:
Voiceover:
Purpose:
```

Gate to continue:

- Each scene has one job.
- The sequence makes sense without explanation from the creator.
- The visual teaches, not just decorates.
- The Short still works if watched without sound.

### Stage 6: Image Prompt Pack

Only after the scene plan is strong, create image prompts.

Each prompt should be saved with:

- video ID
- scene number
- prompt version
- intended lesson purpose
- expected visual elements
- negative prompt or avoid list
- generation tool/model
- final selected image filename

Gate to continue:

- The prompt directly supports the teaching purpose.
- The visual is not generic AI decoration.
- The frame has room for captions and watermark.
- The image can work in 9:16 vertical format.

### Stage 7: Image QA

Generated images must be reviewed before image-to-video spending.

Check:

- Does the image communicate the concept?
- Is the subject clear on mobile?
- Is there space for text?
- Does it avoid misleading math or fake diagrams?
- Does it avoid random robot/brain/cyber clichés?
- Does it match the channel visual style?

Decision:

```text
Approve / revise / reject
```

Do not send rejected or unclear images to image-to-video.

### Stage 8: Image-To-Video Prompt Pack

Only approved images move to motion generation.

Each motion prompt should include:

- starting image filename
- scene number
- motion goal
- camera movement
- object movement
- text-safe area
- avoid list
- duration

Gate to continue:

- Motion clarifies the concept.
- Motion does not distract from the explanation.
- Motion does not make text unreadable.
- Motion does not add incorrect visual information.

### Stage 9: Motion QA

Check before assembly:

- Is the motion smooth?
- Does the image stay legible?
- Does the concept remain clear?
- Are there artifacts?
- Does it work on a phone screen?
- Does it leave space for captions and watermark?

Decision:

```text
Approve / revise / regenerate / replace with still image
```

Important:

If motion does not improve the teaching, use the still image. Do not spend more just to make everything move.

### Stage 10: Voiceover

Voiceover may be the bottleneck, so it should be separated from the rest of the pipeline.

Prepare scripts in advance so recording can happen in batches.

Voiceover options:

1. Creator voice
2. AI scratch voice for timing only
3. Final AI voice if acceptable for the channel
4. Hybrid: creator voice for long-form, AI or text-led Shorts for some Shorts

Recommended workflow:

- Use scratch voice or text timing during assembly.
- Record creator voice in batches when environment is quiet.
- Keep scripts short enough for quick retakes.
- Maintain a voiceover-ready queue.

Voiceover-ready means:

- final script approved
- pronunciation notes added
- timing estimated
- difficult words simplified
- no scene still waiting on explanation changes

### Stage 11: Assembly

Assembly should use reusable templates.

Every Short should include:

- hook frame
- burned-in watermark
- captions
- visual explanation
- memory sentence card
- final brand tag

Every long-form video should include:

- short title card
- watermark
- chapter or transition cards only when useful
- visual explanation segments
- memory sentence
- next-video end card

### Stage 12: Final QA

Before scheduling:

- watch on desktop
- watch on phone
- watch muted
- check captions
- check watermark
- check spelling
- check math accuracy
- check pacing
- check first 2 seconds
- check final brand card
- check title and description

Only then schedule.

## Stage Gates Summary

| Stage | Main question | Move forward only if |
|---|---|---|
| Topic | Does this fit the channel? | It connects Class 9-12 math to AI |
| Learning core | Is the teaching idea clear? | One concept, one mechanism, one memory sentence |
| Scene plan | Does the explanation flow? | Each scene has a job |
| Image prompts | Are visuals purposeful? | They teach, not decorate |
| Image QA | Is it worth animating? | Clear on mobile and conceptually accurate |
| Motion prompts | Does motion help? | It clarifies the idea |
| Motion QA | Is it usable? | Smooth, legible, accurate |
| Voiceover | Is narration final? | Ready for batch recording |
| Assembly | Does it feel like the brand? | Template and pacing are consistent |
| Final QA | Can this be published? | No obvious teaching, visual, or brand issues |

## Batch Strategy

Do not produce one video end-to-end at a time.

Batch by stage:

- plan 30 topics at once
- write 10 learning cores at once
- create 10 scene plans at once
- generate images for 3-5 videos at once
- record voiceover for 5-10 Shorts at once
- assemble 5 Shorts at once

This reduces context switching and protects motivation.

## Cost-Control Rules

Before paid image generation:

- learning core must be approved
- scene plan must be approved
- image prompt must name the teaching purpose

Before paid image-to-video:

- still image must pass Image QA
- motion must have a clear teaching reason
- no expensive generation for purely decorative scenes

Before paid voice tools:

- script must be final
- scene timing must be known
- pronunciation must be checked

## Inventory Targets

Before launch:

```text
10 Shorts fully finished
10 Shorts voiceover-ready or assembly-ready
10 Shorts at scene-plan stage
3 long-form candidates at learning-core stage
```

After launch, never let the buffer drop below:

```text
2 weeks of scheduled videos
2 weeks of finished backups
1 month of planned scripts
```

## Weekly Operating Rhythm

Suggested weekly rhythm:

| Day | Work |
|---|---|
| Monday | topic planning, learning cores, analytics review |
| Tuesday | scene plans and scripts |
| Wednesday | image prompts and image QA |
| Thursday | motion prompts and motion QA |
| Friday | voiceover and assembly |
| Saturday | final QA and scheduling |
| Sunday | rest or light idea capture |

This can be adapted, but the point is to assign stages to days.

## Motivation-Proofing

When motivation is high:

- create future topics
- write scene plans
- record voiceover batches
- build reusable templates

When motivation is low:

- review image QA
- clean metadata
- schedule finished videos
- organize prompts
- make small script edits

The pipeline should always offer a low-energy useful task.

## Pipeline Health Check

Every week, ask:

```text
Where is the bottleneck?
```

Possible answers:

- not enough topics
- weak scene plans
- images not teaching clearly
- motion too expensive or unnecessary
- voiceover delayed
- assembly too slow
- QA finding too many issues

Then fix the bottleneck, not the whole system.

## Bottom Line

The channel should be launched only when the first month is already secure.

The operating system should always keep future work moving one or two stages behind current production, so the channel never depends on one burst of motivation or one perfect recording day.
